# How to Use the Library

**Source:** `HOW_TO_USE.docx` from STORAGE v1.0.0 (last updated 27 September 2025). The original is organized as four steps; these are retained below with links to public adaptations.

## Step 1 — Locate the right workstream

The original archive has numbered workstreams: **10 — Gathering Requirements**, **20 — Architecture and Systems Design**, **30 — Task Definition for Development**, **90 — Release Notes**.

In the public portal these map to [Requirements](requirements/overview.md), [Architecture](architecture/overview.md), [Engineering](engineering/overview.md) and [Release Notes](release-notes.md).

## Step 2 — Select artifact type

- **Template:** reusable blank document structure.
- **Example:** filled sample explaining what a completed deliverable can look like.
- **FAQ / How-to:** design guidance, terminology and trade-offs.

## Step 3 — Adapt to your project

The source says: keep the useful structure, replace placeholders, and consult filled examples for formatting and tone. Do not reuse the fictional targets as measured or certified values.

## Step 4 — Track changes and version the adaptation

Update version/date and keep a change record. See [Versioning Policy](library-versioning.md).

**Source conventions:** Draw.io for diagrams (optional PNG export); PlantUML for sequences; `ARTIFACT_TYPE_[Template|Example|FAQ]` style naming.

### Additional public-edition guidance

Do not include real bank/client identifiers, secrets, PAN/CVV, nonpublic network topology or third-party material you cannot license. Review unknown transaction outcomes and third-party API contracts before using payment diagrams in production.

Start at [Downloads](downloads.md) and [Examples](examples/source-examples-downloads.md). See the [License](license.md) and [44-file Inventory](source-inventory.md).
